# 统一摄像机求值

当前正常播放由 GSAP tween 与 Pixi ticker 更新镜头，seek/export 则通过独立解析器重建镜头状态，两条路径需要分别维护行为。本方案让播放、seek、bake 和 export 消费同一套摄像机求值规则，先消除状态计算分歧，缓动函数暂时继续使用 GSAP。

领域术语见[镜头与投影词汇表](../camera-language.md)。

## 已确认的范围

- 先统一摄像机求值，保留 GSAP 缓动函数；完全解除摄像机对 GSAP 的依赖属于后续阶段。摄像机接口消费求值结果，使用项目类型表达输入输出。
- 保留场景格式与创作意图，允许修正现有行为不一致；跟随手感等可见变化需要记录并评估。
- 在相同场景时间、镜头编排和角色锚点输入下保证镜头结果一致；角色姿态及部位锚点的确定性由角色系统负责。

## 运动与时间

- 后一个动作在自身开始时从当时的实际镜头状态接管所写通道，结束后保持结果，被接管的旧动作不再恢复。x、y、缩放和旋转独立接管；显式提供完整位置的动作同时接管两轴。
- 构图聚焦捕获动作开始时的目标锚点，执行一次固定目标移动；持续追踪由跟随表达。
- 构图聚焦开始时目标角色存在但没有有效锚点，本次位置移动不生效并返回警告；缩放和旋转照常执行，之后不重新捕获目标。始终不存在的角色引用仍是验证错误。
- 路径首关键帧位于动作开始之后时，从动作开始时的实际属性值过渡到该关键帧；首关键帧时间为零时立即采用其值。
- 路径按各属性自己的关键帧独立插值，其他属性的关键帧不会切断其插值区间。仅编排缩放的路径不额外写入位置。
- 关键帧时间决定路径的运动节奏，`durationSeconds` 只补充时间线占用范围；范围较长时保持终态，不拉伸或截断关键帧运动。
- `loop=true` 优先于 `repeat`，表示无限循环；否则 `repeat=N` 表示首次播放后额外重复 N 次，`-1` 表示无限。`yoyo` 控制逐轮往返。有限重复计入动作时长，无限循环只在既定场景范围内运行，不能产生无限长场景。
- 跟随保留持续平滑追赶的意图。需要历史时，显式消费可按场景时间查询的锚点轨迹，并按确定规则重建。
- 后续位置动作自动结束跟随，从该时刻的实际跟随位置开始；动作结束后保持终点。仅修改缩放或旋转的动作保留跟随关系，位置是否被写入以编译后的真实属性轨道为准。
- 跟随目标失去锚点时保持最后一个有效跟随位置，继续保有跟随关系；目标再次出现时平滑追赶。最后有效位置从轨迹确定性重建，不能读取此前查询留下的状态；始终不存在的目标由场景验证报告。
- reset 开始时立即释放跟随、清除此前晃动，从不含画面抖动的实际镜头状态向默认位置、缩放和旋转过渡。reset 结束后保持默认值，时长为零时立即生效。
- 求值支持任意时间、子帧、重复查询和乱序查询；查询不触发播放事件，不修改角色状态。缓存仅加速计算，结果与此前播放和查询过哪些帧无关。
- `focusOn()`、`shake()`、`executeMotion()` 等独立调用作为临时预览，也由同一求值器执行，不写入场景；seek、重载或正式导出开始时清除。需要保存或导出的运镜通过正式场景编排表达。
- push、pull、pan 等创作意图编译为属性动画，时间曲线与空间路径分别表达。新增真实属性需求时扩展轨道，避免提前实现通用动画框架。

## 坐标、投影与光学

- 世界、局部、画面和编辑器视口坐标分别定义，绘制排序值与空间深度分别表达。单位以合成参考尺寸为准，预览和输出分辨率的换算在明确的转换位置处理。
- 沿用 ADR-0037 的逻辑尺寸约定：保持项目宽高比，短边为 1080 个创作单位；同宽高比的分辨率变化不改变镜头构图。归一化场景位置与创作单位之间显式转换。
- 当前 `z` 调节视差的公式属于明确的艺术化投影模型，不能解释为透视摄像机中的真实深度。当前模型在内部有明确标识，现有场景隐式映射到它；未来新增投影模式时，现有场景继续使用当前模型。本次保留 source 格式，模式的具体标识名属于实现选择。
- 镜头位姿、投影和光学参数分别表达；当前 `zoom` 表示画面缩放，不能等同于空间推近或改变焦距。
- 当前 source 中的 `focus` 属于注视/构图意图；将来的光学对焦另有语义。本次保留已有场景字段，先在领域术语与内部接口中区分。

## 组合与渲染

- 当前组合顺序为基础属性动画、有效跟随及其既有位置钳制、艺术化投影与镜头平面旋转、画面抖动、后续镜头效果，再做编辑器视口或输出像素换算。后续位置写入按既定规则释放跟随。
- 当前二维晃动明确为投影后的画面抖动，以合成创作单位计量，在编辑器视口和输出像素换算之前叠加；世界空间和摄像机自身方向的晃动是不同的未来能力。
- 构图约束在内部具有明确策略，本次不新增可保存的创作参数。普通 follow 保留既有位置钳制，构图聚焦允许越界；旋转导致的额外露边只警告，不为此改变镜头位置、缩放或旋转。旋转后的警告规则不替代普通 follow 的原有钳制。
- 露边诊断作为求值结果的数据返回，由调用方呈现和去重；纯求值本身不触发日志或播放事件。
- 镜头平面旋转本次进入实际投影：角色、环境层和图片按统一规则绕画面中心旋转；字幕等画面 UI 保持独立。已填写但此前未生效的旋转值会改变画面，需要纳入迁移说明与验收。
- 摄像机求值与投影、渲染分别设接口，渲染消费所需的镜头信息。多摄像机、父子控制器、透视渲染、完整三维旋转、光学景深和运动模糊随实际功能需要加入数据字段与渲染能力；本次保留任意时间采样及概念上的接入位置。

## 当前实现需要处理的差异

- `Projection.ts` 当前按 `1 + z / 500` 影响位移视差，`500` 是艺术化模型常数，不能因其现有变量名就当作物理焦距。
- `Live2DCharacterGeometry` 与部分环境层把同一个 `z` 同时用于视差与 `zIndex`；新模型分清两个含义，兼容转换保留旧字段同时影响两者的既有效果，未来有独立编辑需求时再增加 source 字段。
- 当前公共投影函数只消费位置、缩放和画面晃动，尚未消费镜头旋转。
- 当前 source 编译器与验证器拒绝跟随期间的位置运镜，不能假设按通道接管规则已经覆盖该情形。
- Hitchcock 已退役，`docs/CAPABILITY.md` 已记录这一事实；当前类型、parser、compiler、resolver 与 runtime 仍有残留。本次清除其入口与实现，遇到存量语句明确报错并提示改用标准运镜，不静默降级。这是保留场景格式与创作意图原则的明确例外，需要列入迁移说明。

## 收敛与验证

上述行为决定已在设计访谈中逐项确认，用户已确认完整设计达成共识。数值原型已验证候选历史跟随求值规则，下一阶段形成实现规格与任务；原型不替代正式引擎实现。

跟随的确定性历史重建需要可运行的证据。数值原型比较了候选重建规则与高精度参考轨迹，覆盖移动和静止目标、锚点缺失与重现、缩放变化、停止与接管、子帧、乱序查询以及冷暖缓存。原型记录误差、锚点采样次数、长场景首次查询及缓存后查询耗时，供后续规格确定积分精度与缓存策略；目前不锁定生产步长或性能承诺。

### 数值原型证据

原型已完成，保存在 `prototype/camera-follow-evaluation` 分支，提交 `ed5e783`。该分支中的 `docs/design/camera-follow-prototype-results.md` 为结论报告，`src/engine/prototypes/camera-follow.prototype.html` 为可独立打开的交互演示，旁边的 benchmark 与 JSON 保存可重复运行的数值实验和原始观测。后续实现规格与任务应引用该提交；原型不合入正式引擎。

- 在 11 个合成场景、120 步/秒候选中，重复、乱序、冷暖缓存及不同预览 fps 查询后的同刻结果，最大观测差均为 0。
- 分段线性目标积分在本轮采样点的最大误差为：120 步/秒约 0.575，240 步/秒约 0.150 合成创作单位。240 步/秒可作为后续候选，不构成任意真实轨迹的误差上界或正式默认值。
- 轨迹输入应提供版本、不连续事件时刻及有效性区间，明确事件左右侧取值；隐去已知事件后，240 步/秒下部分案例误差升至约 5–13 个创作单位。
- 十分钟合成轨迹、240 步/秒、一秒检查点时，本机三次观测中位数为首次查询约 293 ms，已有检查点后的回查约 0.399 ms。首次查询进行了约 28.8 万次锚点采样，正式实现须评估廉价轨迹准备、分段预计算或后台准备，不能由暖缓存耗时推断首次 seek 成本。
- 测量使用 Node v22.22.1 与合成锚点，未覆盖项目要求的 Node >=24、真实 Live2D、正式投影或实际导出。数值基准退出状态为 0，两个内联脚本语法编译通过；没有新增测试套件，也未进行浏览器视觉检查。

后续实现还应落实并在规格中明确以下规则：

- 同时刻动作沿用 source 与编译产物的稳定顺序，后写入者按属性接管；零时长动作立即写入。
- 初始尚无锚点的跟随保持进入前的位置，目标首次出现后再开始追赶；锚点缺失期间的位置与重新进入均由完整轨迹重建。
- 编排、锚点轨迹或合成参考尺寸变更后，相关派生缓存失效；冷暖缓存、查询顺序和预览/导出 fps 均不能改变同一输入的结果。
- 多个画面晃动沿用有限区间内的可重复叠加，结束后归零；reset 按稳定语句顺序释放此前晃动。
- 跟随和临时预览统一从摄像机求值结果写入镜头，删除 GSAP tween、Pixi ticker 对相同镜头属性的竞争写入。场景时钟和播放事件由引擎负责。
- 验收覆盖播放、seek、bake、export 的相同输入一致性，投影旋转、预览/输出分辨率换算、退役输入拒绝，以及求值无事件和角色状态副作用。数值原型不能替代实际引擎集成检查。
